The first public release of ElastiCORE 3.0.

ElastiCORE reads a YAML model of a business domain and generates a Spring Boot application. Generation is now a **rule engine**: rule sets selected by architecture (layered, DDD, hexagonal), language (Java, Kotlin, TypeScript) and Spring Boot version (3 or 4). The 2.x generator is still there and keeps producing its output.

This is an alpha: the output of the v3 bundles (`jpa-springboot-v3`, `ddd-*`, `hexagonal-*`, `*-kt`, `ts-model`) may change before 3.0, each change listed with its reason. A project that declares none gets what 2.x generated.

Artifacts on Maven Central:
- `io.elasticore:elasticore-base`
- `io.elasticore.springboot3:elasticore-springboot3`
- `io.elasticore.springboot4:elasticore-springboot4`
- the Gradle plugin `id 'io.elasticore'`

### Bug fixes

**Output that differs from 2.x**, where 2.x had a defect:
- **`string(n)` with `@length(min=..)`:** the minimum length now reaches `@Size`, so a shorter value answers 400.
- **`@formula`**
  - An expression containing `=` no longer breaks the generated `@Formula`.
  - The mapper does not copy a `@formula` field from the DTO to the entity.
  - The entity field gets `@Formula` only, with no `@Column` creating a real column. Drop such a column from the database yourself.
- **Search DTO:** two `@ManyToOne` relations to the same entity are both searchable; 2.x flattened only the first. These are the 2 ACCEPTED differences `elcoreRulesCheck` reports.
- **Mapper:** a `@forceupdate` field that needs a conversion compiles.
- **Generated service tests:** fields of fully qualified types such as `LocalDateTime` and `BigDecimal` get a value instead of `null`.

**Reading order:** domains and model files are read in name order (case-insensitive) on Linux and macOS, as on Windows. The model, the order of DSL warnings and multi-entity artifacts no longer depend on the operating system.
- **Runtime libraries** (`elasticore-springboot3`, `elasticore-springboot4`): where security behaviour differs from 2.x, the history says how.
