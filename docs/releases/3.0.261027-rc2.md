The second release candidate of 3.0. The pet store was generated, built and run with a team rules module (`elasticore { rules = [...] }`) on rc1, and each example in the rule guide was checked again. The 2.x generator's output and the `jpa-springboot` bundle are unchanged, apart from a `return: decimal` port method that did not compile.

### New features

- **Guide index:** `blueprint/elasticore-guide-index.md` has one line per guide section, so a reader or an AI assistant can open the right section directly.
- **Ossie model name:** `elasticore { ossieName = '...' }` sets the `name` of the exported semantic model.
- **Search keywords:** v3 search conditions accept `gt`, `gte`, `lt`, `lte` and not-equal (`!=`, `ne`).

### Improvements

- **No `@EnableElastiCore` needed.** The runtime library brings Spring Boot auto-configuration, so ports become beans without the annotation.

### Bug fixes

- **Team rules reach the running application.** The v3 search endpoint validates its request body, so constraints a rule puts on a search DTO take effect. `addMethod` is no longer dropped on a class without methods.
- **Names**
  - A plain DTO named `...SrchDTO` keeps its name. It was generated as `...SrchDTODTO`.
  - A core service refers to its entity by name, even when the service package has a class of the same name.
- **Imports**
  - A DTO extending a DTO of another domain imports its parent.
  - A port of a domain without entities imports no entity package.
- **DBMS port methods:** these now generate correctly:
  - methods that return a single value (`long countX()`, `String`, `BigDecimal`);
  - methods that take a single value (`nameOf(Long id)`);
  - `return: decimal`.
